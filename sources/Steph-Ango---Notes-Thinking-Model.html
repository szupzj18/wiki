One-line summary

Steph Ango treats note-taking as building a durable, file-based thinking environment where small linked ideas accumulate over time into a personal knowledge web.

Core mental models

1. Notes are durable artifacts, not app-bound data

The underlying object is the file, not the app.

  • Notes should remain readable and controllable over decades.
  • Plain text and simple formats matter because tools are temporary.
  • A vault is just a folder, which makes it portable and ownable.

Implication for this vault:

  • Prefer Markdown files.
  • Avoid workflows that only exist inside one proprietary interface.
  • Treat .obsidian as optional tooling, not the knowledge itself.

2. Notes should lower cognitive load, not create admin work

His system is biased toward speed, laziness, and low overhead.

  • Use few folders.
  • Avoid nested hierarchies.
  • Navigate through quick switcher, links, and backlinks instead of browsing trees.
  • Let structure emerge bottom-up.

Implication:

  • Do not over-design taxonomy early.
  • Keep capture friction low.
  • Organize later by links, categories, and reusable properties.

3. Ideas become more useful when turned into small objects

His evergreen note model treats a note as a manipulable unit of thought.

  • Each evergreen note captures one idea.
  • Titles should be short, memorable, and usable in a sentence.
  • Notes can be tiny.
  • Notes do not need to express agreement; they only need to capture a thought clearly enough to reuse.

Implication:

  • Prefer atomic idea notes over long mixed-topic dumps.
  • Give notes titles like claims, not vague topics.
  • Build larger arguments by combining small notes.

4. Linking is how thinking compounds

Links are not decoration. They are the operating system of the vault.

  • Link the first mention of a concept.
  • Unresolved links are useful breadcrumbs.
  • Heavy linking makes the history and evolution of ideas visible.
  • The value of linking increases over time.

Implication:

  • Encourage frequent internal links.
  • Do not wait until a note is “finished” before linking to it.
  • Treat missing notes as invitations, not errors.

5. Concision makes notes composable

Short, strong explanations make ideas easier to combine, challenge, and reuse.

  • A concise note spreads faster in your own mind.
  • It accelerates later decisions because the claim is clear.
  • It increases the chance that one note can connect to another.

Implication:

  • Rewrite notes until the core idea is legible.
  • Prefer one sharp paragraph over diffuse pages of hedging.
  • Extract summary lines from long source notes.

6. Process should be constrained so thinking can stay flexible

He separates flexible thought from repeatable process.

  • Use consistent naming, dates, tags, and templates.
  • Repeated constraints reduce future decisions.
  • Style is leverage.

Implication:

  • Standardize formats such as YYYY-MM-DD.
  • Keep property names short and reusable.
  • Define a small style guide for this vault and let the agent enforce it.

7. Categories and properties beat deep folders

Classification should remain lightweight and cross-cutting.

  • Many notes belong to multiple contexts.
  • Categories are more flexible than a single folder path.
  • Reusable properties allow notes from different domains to be queried together.

Implication:

  • Prefer frontmatter fields like categories, tags, created, source, people, themes.
  • Use folders only for clearly different kinds of material, such as references, clippings, attachments, templates, and admin notes.

8. Journaling is not only logging, it is synthesis

He uses a fractal review system.

  • Capture small fragments quickly.
  • Periodically review and condense them.
  • Revisit reviews at larger time scales.
  • Random revisit helps rediscover forgotten ideas and repair links.

Implication:

  • Separate raw capture from synthesis.
  • Build recurring review notes: daily, weekly, monthly, yearly.
  • Schedule random resurfacing of old notes.

9. Maintenance is part of understanding

He explicitly rejects outsourcing all note maintenance to automation.

  • Revisiting, cleaning, and relinking are forms of thinking.
  • Delegating everything can weaken understanding.

Inference:

  • Agent automation should support understanding, not replace it.

Implication for agent autonomy:

  • The agent can collect, normalize, link, and propose summaries.
  • Final interpretation, pruning, and promotion to evergreen notes should stay reviewable by you.

10. Simplicity requires pruning

A healthy system removes as well as adds.

  • Without pruning, systems grow until they become hard to use.
  • Removal is invisible but essential maintenance.

Implication:

  • Periodically archive stale notes.
  • Merge duplicates.
  • Remove dead templates and unnecessary structure.
  • Favor subtraction when the vault starts feeling heavy.

A practical model for your vault

If we adapt Steph Ango’s thinking for an agent-maintained vault, the vault should behave like this:

  1. Capture fast into plain Markdown files.
  2. Normalize metadata and naming consistently.
  3. Turn important ideas into atomic evergreen notes.
  4. Link aggressively across notes, including unresolved ideas.
  5. Use lightweight folders only where type boundaries are obvious.
  6. Organize by reusable properties instead of nested trees.
  7. Review and prune on a schedule so the vault stays alive.

Suggested role split between you and the agent

Agent should do

  • Import and summarize articles.
  • Create draft notes with clean titles and metadata.
  • Suggest links, categories, and candidate evergreen notes.
  • Generate weekly and monthly review stubs.
  • Detect duplicates, stale notes, and missing backlinks.

You should do

  • Decide which ideas are actually worth keeping.
  • Refine the wording of evergreen notes.
  • Confirm interpretations that matter.
  • Use review sessions to deepen understanding instead of only filing information.

Distilled design rules

  • File over app.
  • Link over folder.
  • Property over path.
  • Concision over exhaustiveness.
  • Reuse over reinvention.
  • Review over hoarding.
  • Prune over accrete.
  • Support understanding, do not automate it away.

Candidate operating principle for this vault

This vault should optimize for long-term readable files, low-friction capture, dense linking, reusable metadata, and periodic synthesis.
