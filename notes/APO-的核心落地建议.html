APO 的核心落地建议

APO 最值得落地的地方，不是“让模型帮你写一个更漂亮的 prompt”，而是把 prompt 调优变成一个有样本、有指标、有候选集、有迭代记录的工程流程。

什么时候值得用 APO

  • 任务会重复运行，prompt 质量的提升能持续复用。
  • 输出有相对明确的评价标准，例如分类准确率、抽取 F1、格式合规率、人工打分 rubric、编辑距离、SARI、ERRANT 等。
  • 已经有一批代表性输入输出样本，最好能分成 train / validation / test。
  • 当前 prompt 对措辞、示例顺序、格式、模型版本变化很敏感。
  • 人工 prompt 调优已经进入反复试错，但缺少可复现记录。

不适合直接上 APO 的场景：一次性任务、没有评价标准的开放写作、样本极少且不可补、目标本身还没定义清楚。

最小可行落地流程

  1. 固定任务边界：写清楚输入、期望输出、禁止行为、输出格式、失败样例。
  2. 准备数据集：至少准备几十条代表性样本；保留一个不参与优化的 test set。
  3. 设计评价函数：优先用自动指标；主观任务用 rubric + 人工抽检；关键约束单独做硬性检查。
  4. 生成候选 prompt：从人工 seed、LLM 归纳、示例诱导、改写、重排、增删规则中产生多个候选。
  5. 小批量评估：先用 validation 子集快速淘汰差候选，再扩大评估范围。
  6. 记录每轮变化：保存 prompt、分数、错误样本、LLM 批评、采用或拒绝理由。
  7. 最终只在 test set 上评一次：避免把 test set 变成新的调参集。
  8. 人工复核 winner：检查可读性、边界行为、失败类型、过拟合痕迹和上线风险。

论文到实践的对应建议

  • Ramnath et al. 的综述：先把系统拆成五段：seed prompt、反馈信号、候选生成、候选筛选、迭代深度。落地时不要一开始追求复杂算法，先把这五段的接口和日志做清楚。
  • APE：当你没有好 seed prompt，但有输入输出样本时，让 LLM 先从样本中归纳多条候选指令，再用验证集筛选。适合冷启动分类、抽取、简单转换任务。
  • APO / ProTeGi：当已有 prompt 但错误类型明显时，用“错误样本 → 自然语言批评 → 反向编辑 prompt”的循环。适合把含糊任务说明改成更精确的判定标准。
  • Li et al. 的优化视角综述：先判断你优化的变量是什么。普通 API 场景优先优化离散 prompt、示例选择、示例顺序；有权重或 embedding 权限时再考虑 soft prompt / gradient 方法。
  • APIO：对于改写、纠错、简化这类文本修订任务，把 prompt 拆成有序的短指令列表，再对单条指令做 improve、rephrase、permute，比整体改写一大段 prompt 更可控。
  • AutoPDL：做 agent 时不要只调 system prompt，还要搜索 agent pattern，例如 zero-shot、few-shot、CoT、ReAct、ReWOO、工具调用结构。最终产物最好是可读、可执行的 prompt program。
  • iPrOp：当指标不能覆盖业务判断时，把人放进循环。让人看高信息量样本、候选 prompt、模型解释和指标，而不是只在最后验收一个黑盒结果。

实操中的关键约束

  • 数据比算法更重要：validation set 不代表真实分布时，APO 会稳定优化到错误方向。
  • 指标必须拆开看：总分提高可能掩盖格式合规率下降、拒答率上升、召回下降或风格变差。
  • 候选要保留多样性：只做局部改写容易早早收敛到次优 prompt。
  • 优化预算要受控：限制候选数量、每轮样本数、最大迭代轮数和单轮 API 成本。
  • Prompt 必须可审计：上线版本要能解释为什么改、解决了什么错误、在哪些样本上变好或变差。
  • 不要只优化单模型：如果生产会换模型或并行使用多模型，winner prompt 需要跨模型回归测试。

一个可直接采用的工程模板

  • dataset/train.jsonl：用于生成批评、示例、候选 prompt。
  • dataset/val.jsonl：用于每轮候选筛选。
  • dataset/test.jsonl：只用于最终评估。
  • prompts/candidates/：保存每轮候选 prompt。
  • runs/{date}/scores.csv：记录候选、指标、成本、模型、温度、样本数。
  • runs/{date}/errors.md：记录失败样本和错误类型。
  • runs/{date}/decision.md：记录最终选择、拒绝的候选、风险和人工复核结论。

最推荐的落地起点

从一个轻量黑盒 APO loop 开始：固定 50-200 条验证样本，保留 5-10 个候选 prompt，每轮让 LLM 基于错误样本提出 3-5 条修改建议，再用自动指标和人工抽检筛选。等这个流程能稳定复现收益，再考虑 beam search、successive halving、agent pattern search 或人机交互界面。
