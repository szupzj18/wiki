We might all be AI engineers now

Summary

A Hacker News discussion debating the impact of LLM coding tools on software engineering. The conversation splits into two broad camps: proponents who describe the tools as supercharged code search and autocomplete delivering 10% to multi-fold productivity gains, and skeptics who argue LLM code is locally passable but globally incoherent, prone to hidden technical debt and security flaws. The discussion also covers the K-shaped workforce split, the cognitive load of reviewing AI output, the redefinition of engineering skills, and broader societal concerns about labor displacement and corporate control of AI tooling.

Key Takeaways

  • AI coding tools create a K-shaped workforce split between skilled augmented engineers and those unable to leverage them well.
  • LLM-generated code is locally functional but globally incoherent, tending to produce hidden technical debt that is hard to debug.
  • Effective AI coding shifts the workflow toward treating output as hypotheses to be validated through tests and specs, not code to be passively reviewed.
  • The cognitive load of reviewing AI output is real and qualitatively different from writing code yourself, contributing to burnout.
  • Anecdotal productivity claims conflict sharply with formal studies that show minimal measurable gains, partly because many studies predate modern RLHF models.
  • Traditional engineering skills are being redefined rather than obviated — judgment, specification, and verification become the core value.
  • Spec-driven development is rising as AI shifts coding toward writing clear, unambiguous requirements and formal specs.

Detailed Discussion Breakdown

Theme 1: AI Productivity Claims, Measurement & Workflow Shifts

  • noemit: AI quietly writes strong code most of the time; people only share failures. Works with global engineers of varied skill; CA startup engineers see ~10x gains. Skilled guidance is required, creating a K-shaped workforce. (Pro-AI)
  • bryanrasmussen: Questions how pro-AI users report productivity gains despite third-party HN-posted studies showing no measurable gains. Later asks about ticket structuring for successful AI workflows. (Skeptical, evidence-seeking)
  • peteforde: Frustrated by demands to quantify obvious gains. Uses Opus 4.5 via Cursor ($200/month base + $50-100 overages; peak $700/month). Calls less powerful models produce bad results skeptics generalize. AI is cheaper than unreliable human hires — LLM $3600/year vs. hiring. (Strongly Pro-AI)
  • remus: Compares AI productivity studies to flawed power tool vs. hand tool studies; a chainsaw user would laugh at claims of no gains. (Pro-AI)
  • KronisLV: Sees 3-5x personal gains using Claude Code + $100/month Opus 4.6 Max. Notes 80% of devs may see marginal or detrimental gains due to learning curve. Previously used Cerebras Code but GLM 4.7 needed frequent fixes. (Pro-AI with caveats)
  • prescriptivist (principal engineer, 10yrs same codebases): Increased inbound volume handled faster; first time chipping away at “nice-to-have” backlog. SEV rates unchanged; code review volume near breaking point. 20% of work inbound throughput increase. (Pro-AI)
  • overgard: Personal 10-20% gains; uses AI for repetitive React form code; uses as rubber duck for idea bouncing. Data editor project generating many repetitive fields. (Mixed, daily user, moderate gains, anti-hype)
  • sameerds: AI acts as supercharged code search/autocomplete; saved 1 week finding rare complex component changes; acts only as reviewer. (Pro-AI)
  • SquibblesRedux: Defines LLMs as supercharged search + autocomplete + adjustable randomness. (Neutral/Pro-AI)
  • _zagj: Most productivity studies predate modern RLHF models; 10x claims unfounded; AI is only improving. (Mixed, pro-adoption, anti-hype)
  • codebolt: Effective prompting requires formal, detailed specs (“formal letter to British throne” level clarity); many devs lack this writing skill. Contrasts old Google keyword-search habit. (Pro-AI, workflow skill shift)
  • pragma_x: Unambiguous specs + jargon/CS formalisms/patterns prevent LLM “creativity”; coding now equals robust requirements doc writing. Compares unwanted AI creativity to unwanted intern creativity. (Pro-AI)
  • ValentineC: Spec-driven development rising; devs use AI to write prompts for other AI to write code. (Neutral/Pro-AI)
  • sdf2df (CEO): Revamped hiring to test thinking, not coding. Personal Grok video project produced good output but was extremely painful and costly (50 free Grok accounts, tens of thousands in implied costs); preferred humans. (Mixed, pro-thinking hiring, skeptical of production LLM use)

Theme 2: AI Code Quality, Architecture & “Hallucinations”

  • overgard: AI code locally functional, globally incoherent; happily generates architecturally bad code; LLMs perform worse as codebases grow; AGENTS.md worsens outcomes. (Skeptical of unguided AI)
  • jihadjihad: Proposes agent context rule: changes at layer N require consideration of layers N-1 (dependencies) and N+1 (consumers), analogous to grep -A/-B context flags. Untested proposal. (Mixed, identifies problem, proposes untested fix)
  • archagon: AI code will create “future full of horrifying security holes, heisenbugs”; agentic programming is management of non-improving workers; models owned by “authoritarian, billionaire, misanthropic cultists”. Warns of $20/month subscription price jumping 10x on market capture. (Strongly Skeptical)
  • _dwt: Identifies “hallucination-adjacent” issues: incorrect numerical algorithm parameters, failed fix loops from missed steps, subtle domain-specific algorithm choices. Personal experience with typed/tested code with no non-existent function calls, but other subtle errors. (Skeptical)
  • johnfn: “Hallucinations are irrelevant in practice; learn AI’s weak domains and avoid them.” Compares complaining about hallucinations to using a hammer on screws and blaming the tool. Cites typical HN skeptic absurd claims (GPT 3.5 = Opus 4.6 interchangeable, attacks on engineering ability). (Pro-AI)
  • choutos: Reframe AI output as hypothesis, not code to review; shift workflow to tests/validation/specs; deliverable is proof of correctness, not code. Teams making this explicit shift adapt best. (Pro-AI with workflow adjustment)
  • scott_s: AI effectively makes everyone tech leads; review/validation role is not new. (Neutral/Pro-AI)
  • kif: LLMs excel at prototyping/boilerplate; Claude’s mistakes are non-negligible; dual coding+review role causes burnout/higher cognitive load for self and colleagues. (Mixed)
  • sn0wflak3s (article submitter): Cognitive load of reviewing AI output is real and different from writing code; reviews every AI-generated line non-negotiably; improves with tighter feedback loops/testing. (Mixed, pro-AI with caveats)
  • kdheiwns: Engineers fix problems when noticed; AI “sends happy little emoji while it continues to trash your codebase” to total unmaintainability. (Skeptical)
  • skydhash: Quotes Dijkstra (EWD249, EWD667) to note clear thought/structured complexity is always essential engineering skill. (Neutral/Pro-clear-thinking)
  • godelski: Quotes Dijkstra (EWD288) to note “program correctness concern repulsive to many programmers”; LLMs double down on “it works therefore it’s correct” mindset. (Skeptical)
  • Anamon: AI increases superficial short-term productivity but may cause extreme technical debt wiping long-term gains. (Skeptical)
  • wk320189: Dismisses tern’s points as “standard AI promotion talking points”; demands proof of working code. (Skeptical)

Theme 3: Skill Obsolescence, Labor & Historical Analogies

  • prescriptivist: Traditional engineering skills are “more or less obviated now”; genie out of bottle, no labor movement/deus ex machina reversal. (Pro-AI, resigned to change)
  • lll-o-lll: Compares current moment to 19th-century British textile weavers (Luddites). Acknowledges AI output inferior but irrelevant; governments will not protect skilled workers; all factory-processable work at risk. Not hopeful for better societal outcomes. (Skeptical/negative acceptance)
  • dasil003: Software already automates manual work + simpler programs; LLM is a large non-deterministic, leaky abstraction hop; traditional manual coders “cooked”; adapting to LLM tooling offers bright future. (Pro-AI, adaptation message)
  • archagon: Rejects obsoletion claims; LLMs not intelligent, limited by training corpus; craft undervalued by pro-AI folks eager to be PMs; not beholden to “AI-pilled corporation” salary. Mitch Hedberg cook/farm analogy for agentic programming critique. (Strongly Skeptical)
  • bandrami: Never had to learn JavaScript 20 years ago or blockchains 5 years ago; still uses Perl; does not have to learn AI agents. Companies more hesitant to adopt AI than individual devs due to legal/TCO concerns. (Skeptical of inevitability)
  • KronisLV: Not learning AI practicalities makes developers less competitive; corporations do not care about AI flaws; compares to JavaScript learning enabling 5-10 years of paid work. (Pro-AI, market pressure argument)
  • norir: Claims AI can write code equal in quality to manually typed code only applies to the claimant personally. (Skeptical)
  • thunky: Some programmers see too much value in their own work; obsolescence is not punishment. (Neutral/Skeptical of craftsmanship sanctity)
  • overgard (response to thunky): Calling craftsmanship obsolete equals punishing care and quality. (Skeptical)
  • Anamon: Models utterly fail outside training corpus space; 2022 software would be peak capability if progress stops; security/reliability progress reversed entirely. (Strongly Skeptical)

Theme 4: Societal, Ethical & Political Concerns

  • _dwt: Rejects AI inevitability; humanity can choose not to deploy transformative tech (nuclear weapons used twice only); CEOs calling LLMs bigger than fire/nukes are “psychopathic”; public widely distrusts AI; pushes for data royalties/planetary sovereign wealth fund. Cites supersonic airliners, eugenics, Betamax as examples of world-changing tech not widely adopted. (Strongly Skeptical)
  • prescriptivist: Agrees humanity could stop AI but capital is too powerful; business pays bills/healthcare; larger revolution against capital only solution; acknowledges participation may seed end of own career. (Pro-AI, resigned to capital pressure)
  • solaire_oa: Recommends local LLMs (llama.cpp) to democratize AI; removes reliance on centralized providers; hedges against provider investment unsustainability. (Mixed, pro-AI with local deployment)
  • overgard: Trillions poured into barely-understood tech for awful economic revolution not inevitable; need non-idiot leaders; normies waking up to issues; need working SEC to punish grifting CEOs manipulating markets with fear. (Strongly Skeptical)
  • palmotea: AI dumped into 2026 extractive shareholder economy; AI designed to eliminate well-compensated knowledge workers; few workers running hot burning out with mass idle low-wage replacements. (Strongly Skeptical)
  • salawat: Criticizes tern’s “taste” claim as armchair theorizing; capitalism’s optimization function is capital allocation, not craftsmanship. (Skeptical)
  • godelski (AI researcher): LLMs trained for human preference/accuracy/natural speech maximizes their ability to deceive humans; warns against self-delusion of being uniquely unaffected. (Skeptical)

Building complex custom PL/bytecode/runtime with formal specs, algebraic topology, obscure PL concepts. Notes heavy chatbot reading is making own writing style chatbot-like; plans 19th-century literature reading fix. (Pro-AI)
  • godelski: Disagrees LLMs are effective learning tools; “swiss cheese knowledge” from skipping textbook/prose learning; same mechanism causes conspiracy theories; textbooks converged to current structure for good reason. Complexity (computational + conceptual) is real bottleneck, not hands/ideas. (Skeptical of LLM learning)
  • samiv: AI draws lazy non-learners; like skipping to math book answers; global school LLM cheating crises. (Skeptical)
  • johnfn: More to learn now than ever pre-AI; spends more time learning previously out-of-reach topics. (Pro-AI)
