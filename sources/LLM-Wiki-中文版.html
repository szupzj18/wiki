LLM Wiki（中译）

一种使用 LLM 构建个人知识库的模式。

原文：https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f 作者：Andrej Karpathy

这是一个”想法文件”，设计目的是让你复制粘贴给自己的 LLM Agent（例如 OpenAI Codex、Claude Code、OpenCode / Pi 等）。它的目标是传达高层思路，具体细节由你的 Agent 与你协作构建。

核心思想

大多数人使用 LLM 处理文档的体验是 RAG：你上传一堆文件，LLM 在查询时检索相关片段，然后生成答案。这能用，但 LLM 每次都在从零重新发现知识，没有积累。问一个需要综合五份文档的微妙问题，LLM 每次都得重新查找、拼凑相关片段，什么也没有沉淀下来。NotebookLM、ChatGPT 文件上传以及大多数 RAG 系统都是这样工作的。

这里的思路不同。LLM 不只是在查询时从原始文档中检索，而是增量地构建和维护一个持久化的维基——一个结构化、互相链接的 markdown 文件集合，位于你和原始资料之间。当你添加新资料时，LLM 不只是为后续检索做索引，而是阅读它、提取关键信息，并整合进现有维基——更新实体页面、修订主题摘要、标注新数据与旧结论矛盾之处、强化或挑战正在演进的综合结论。知识只编译一次，然后持续保持更新，而不是每次查询都重新推导。

这就是关键区别：维基是一个持久的、不断复利的产物。 交叉引用已经就位，矛盾已被标记，综合结论已反映你读过的一切。每添加一份资料、每问一个问题，维基都变得更丰富。

你永远（或几乎不）需要自己写维基——LLM 编写并维护全部内容。你负责搜集资料、探索方向和提出好问题；LLM 做所有苦力活——总结、交叉引用、归档和簿记，这些正是让知识库长期真正有用的工作。实践中，我一边开着 LLM Agent，一边开着 Obsidian。LLM 根据我们的对话做编辑，我实时浏览结果——跟随链接、查看图谱、阅读更新后的页面。Obsidian 是 IDE，LLM 是程序员，维基是代码库。

这适用于很多场景，举几个例子：

  • 个人成长：追踪自己的目标、健康、心理、自我提升——归档日记、文章、播客笔记，随时间构建出关于你自己的结构化画像。
  • 研究：在数周或数月内深入一个主题——阅读论文、文章、报告，增量构建一个全面的维基，形成不断演进的论点。
  • 读书：边读边归档每一章，为人物、主题、情节线索及其关联建立页面。读完时你就拥有一个丰富的伴读维基。想想 Tolkien Gateway 这样的粉丝维基——数千个互相链接的页面，涵盖人物、地点、事件、语言，由社区志愿者历时多年建成。你可以在阅读时个人化地建成类似的东西，所有交叉引用和维护都由 LLM 完成。
  • 商业/团队：由 LLM 维护的内部维基，输入来自 Slack 讨论、会议记录、项目文档、客户访谈，可由人工审核更新。维基能保持最新，因为 LLM 做了团队里没人愿意做的维护工作。
  • 竞品分析、尽职调查、旅行规划、课程笔记、爱好深挖——任何需要随时间积累知识并希望它井井有条而非散落各处的场景。

架构

分三层：

原始资料（Raw sources）——你精心收集的源文档：文章、论文、图片、数据文件。它们是不可变的——LLM 只读取，绝不修改。这是你的事实来源。

维基（The wiki）——一个由 LLM 生成的 markdown 文件目录：摘要、实体页、概念页、对比、总览、综合。LLM 完全拥有这一层：创建页面、在新资料到来时更新、维护交叉引用、保持一致性。你读它，LLM 写它。

模式文件（The schema）——一份文档（如 Claude Code 的 CLAUDE.md 或 Codex 的 AGENTS.md），告诉 LLM 维基的结构、约定，以及在摄入资料、回答问题、维护维基时应遵循的工作流。这是关键的配置文件——它让 LLM 成为一个有纪律的维基维护者，而不是通用聊天机器人。你和 LLM 在实践中共同演进它。

操作

摄入（Ingest）。 你把新资料放入原始集合并告诉 LLM 处理。示例流程：LLM 阅读资料、与你讨论关键要点、在维基中写一个摘要页、更新索引、更新全维基相关的实体页和概念页、在日志中追加一条记录。一份资料可能涉及 10-15 个维基页面。我个人偏好一次摄入一份并保持参与——我读摘要、检查更新、引导 LLM 突出重点。但你也可以低监督地批量摄入许多资料。你可以发展适合自己风格的工作流，并把它记录在模式文件中供以后的会话使用。

查询（Query）。 你针对维基提问。LLM 搜索相关页面、阅读它们、综合出带引用的答案。答案可以根据问题采取不同形式——一个 markdown 页面、一张对比表、一套幻灯片（Marp）、一张图表（matplotlib）、一块画布。重要的洞见：好的答案可以作为新页面归档回维基。 你要求的一次对比、一份分析、一个发现的关联——这些都很有价值，不应消失在聊天记录里。这样你的探索就像摄入的资料一样在知识库中复利积累。

巡检（Lint）。 定期让 LLM 对维基做健康检查：页面间的矛盾、被新资料取代的过时结论、没有入链的孤儿页、被提及但缺少独立页面的重要概念、缺失的交叉引用、可以通过网络搜索填补的数据空白。LLM 很擅长建议值得调查的新问题和值得寻找的新资料。这能让维基在成长中保持健康。

索引与日志

两个特殊文件帮助 LLM（和你）在维基成长时导航。它们用途不同：

index.md 是面向内容的。它是维基中所有内容的目录——每个页面带链接、一行摘要，以及可选的元数据（如日期或资料数量）。按类别组织（实体、概念、资料等）。LLM 每次摄入时更新它。回答查询时，LLM 先读索引找到相关页面，再深入阅读。这在中等规模（约 100 份资料、数百页面）下效果出奇地好，无需基于嵌入的 RAG 基础设施。

log.md 是按时间顺序的。它是只追加的记录，记载何时发生了什么——摄入、查询、巡检。一个实用技巧：如果每条记录以一致的前缀开头（如 ## [2026-04-02] ingest | 文章标题），日志就可以用简单的 unix 工具解析——grep "^## \[" log.md | tail -5 给出最近 5 条记录。日志为你提供维基演进的时间线，并帮助 LLM 了解最近做了什么。

可选：CLI 工具

到某个阶段，你可能想构建小工具帮助 LLM 更高效地操作维基。最显而易见的是维基页面的搜索引擎——小规模时索引文件就够了，但维基变大后你需要真正的搜索。qmd 是个不错的选择：它是本地 markdown 文件搜索引擎，混合 BM25/向量搜索和 LLM 重排序，全部在设备上运行。它既有 CLI（LLM 可以 shell 调用），也有 MCP 服务器（LLM 可以作为原生工具使用）。你也可以自己构建更简单的东西——需要时 LLM 可以帮你随手写一个朴素的搜索脚本。

技巧与窍门

  • Obsidian Web Clipper 是一个浏览器扩展，可将网页文章转换为 markdown。对于快速把资料收入原始集合非常有用。
  • 本地下载图片。 在 Obsidian 设置 → 文件与链接中，将”附件文件夹路径”设为固定目录（如 raw/assets/）。然后在设置 → 快捷键中搜索”Download”，找到”Download attachments for current file”并绑定快捷键（如 Ctrl+Shift+D）。裁剪文章后按下快捷键，所有图片会下载到本地。这是可选的但很有用——让 LLM 可以直接查看和引用图片，而不依赖可能失效的 URL。注意 LLM 无法在一次读取中原生理解含内联图片的 markdown——变通方法是让 LLM 先读文本，再单独查看部分或全部引用的图片以获取额外上下文。有点笨拙但足够好用。
  • Obsidian 的图谱视图是查看维基形态的最佳方式——什么与什么相连、哪些页面是枢纽、哪些是孤儿。
  • Marp 是基于 markdown 的幻灯片格式。Obsidian 有对应插件，可直接从维基内容生成演示文稿。
  • Dataview 是一个 Obsidian 插件，可对页面 frontmatter 运行查询。如果 LLM 给维基页面添加 YAML frontmatter（标签、日期、资料数量），Dataview 可以生成动态表格和列表。
  • 维基就是一个 markdown 文件的 git 仓库。你免费获得版本历史、分支和协作。

为什么这有效

维护知识库的枯燥部分不是阅读或思考——而是簿记：更新交叉引用、保持摘要最新、标注新数据与旧结论的矛盾、在数十个页面间保持一致性。人类放弃维基，是因为维护负担的增长快于价值的增长。LLM 不会厌倦、不会忘记更新交叉引用、能一次触及 15 个文件。维基能保持维护，因为维护成本接近于零。

人类的工作是策划资料、引导分析、提出好问题、思考这一切意味着什么。LLM 的工作是其他一切。

这个想法在精神上与 Vannevar Bush 的 Memex（1945）相通——一个个人的、精心策划的知识存储，文档之间有关联轨迹。Bush 的愿景比后来的万维网更接近于此：私有的、主动策划的，文档之间的连接与文档本身同样有价值。他无法解决的问题是谁来做维护。LLM 解决了这个问题。

备注

本文档有意保持抽象。它描述的是思路，而非具体实现。确切的目录结构、模式约定、页面格式、工具链——都取决于你的领域、你的偏好和你选择的 LLM。上述一切都是可选和模块化的——取你所需，弃所不需。例如：你的资料可能是纯文本，那就完全不需要图片处理；你的维基可能小到只需索引文件，无需搜索引擎；你可能不关心幻灯片，只想要 markdown 页面；你可能想要完全不同的输出格式集。正确的使用方式是把它分享给你的 LLM Agent，共同实例化一个适合你需求的版本。本文档的唯一任务是传达这个模式，其余的你的 LLM 可以搞定。
