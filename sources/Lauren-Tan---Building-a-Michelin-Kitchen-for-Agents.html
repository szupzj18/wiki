Building a Michelin Kitchen for Agents

Summary

Lauren Tan（X：@poteto，曾在 React core team，加入 Cursor 六个月，现在在 SpaceX AI 做 Grokbot）的 38 分钟演讲。她上个月向生产环境发布了约 2,000 个 PR，演讲讲的是支撑这个数量的前提：信任。她把环境搭建比作米其林厨房，厨房布置决定了厨师和帮厨能否默认做对事情。

  • 时长：38:01，英文

Key Takeaways

信任是并行度的前提（05:31） 同时管一到五个 Agent 的阶段最难跳出：每个对话都要盯，离开就出错。没有信任就直接拉起一百个子 Agent，得到的是一堆 slop PR 和回归。

验证分两端（07:08）

  • 低端：验证 skill，教 Agent 用 Chrome DevTools Protocol 等手段运行应用、抓 trace、拍 heap snapshot。
  • 高端：Lean、TLA+ 之类的形式化方法，检查业务不变量。她称之为仍是开放问题，“very few people really do that”，用验证 skill 已经能走得很远。

验证 skill = CLI + 功能地图（08:44、10:19） 她的第一个 skill 叫 Control Glass。CLI 放在 skill 目录里，保证每个会话用同一套方式运行应用并收集证据。功能地图（feature map）参考 sitemap，记录应用有哪些功能、用户如何到达（快捷键、DOM 元素），存在 skill 目录里，由自动化维护。Slack 上用户只发一张模糊截图加三个问号时，Agent 靠功能地图才能判断指的是什么。

验证管正确性，代码质量靠另一类 skill（13:20） PStack 插件收集她做调试、功能开发、原型时的工作流，由资深工程师沉淀成团队 skill 库。验证 skill 提供真实的性能数据，两者组合才能同时保证正确和质量。

五层信任阶梯（15:49–18:30，收尾幻灯片 36:12） 从强到弱：代码库本身 → 静态分析（lint、编译器诊断、CI）→ Rules / Bugbot / Skills → 风格指南（只有人工评审能执行）。纠正 Agent 时按这个顺序找落点，优先让错误”在类别上不可能发生”。

代码库是 Agent 的记忆（15:49、21:07） Agent 倾向沿用上下文里已有的模式。已有的反模式会像病毒一样传播：一个 workaround 或解释它的注释，几天到几周内成为所有 Agent 的默认写法。

Dune：对 Agent 友好的框架（19:07–29:00） Grokbot 客户端框架，原则是 Agent 爱走捷径，所以让捷径就是正确的路。对人类可能很烦，因为限制很死，但对上下文很少的 Agent 和非工程师贡献者（设计师、PM、CEO）默认安全。功能集中在单个目录，主进程与渲染进程的代码不允许互相导入，由 import 依赖图强制，这条规则来自 Cursor agent window 的性能教训（渲染线程任务要短于 16ms 才能保 60fps）。

禁止代码注释（24:13） Agent 用注释为”没有真正解决问题、只贴了创可贴”辩护，所以 Dune 直接禁止注释，避免这种模式扩散。

“园丁”角色与三条原则（22:04、24:34–26:30） 每个团队需要一个园丁：删除已有技术债；为多数场景保留一条标准路径（paved path）；看到坏模式的第一反应是写 lint 规则，不必立刻清理，先止血，再让 Agent 清理，保持代码库处在”Agent 抄了也不吃亏”的状态。

外层循环（32:45–34:00） Grokbot 连接 Slack、Datadog、Sentry、PlanetScale 等，通过 routines 订阅事件，自动拉起 cloud agents。她认为不需要”公司大脑”之类的复杂基础设施，Agent 本来就会用工具。
